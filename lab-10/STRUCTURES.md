# ЛР-10. Структури папок

Ці таблиці заповнюєте ви: «У яких теках лежить кошик» — по рядку для
стартової структури (§4.3) і для гібридної (§4.7), «Вибір структури» — у
§4.8. Рядок «Пакет» — лише якщо виконуєте додаткове завдання §4.10. Як
рахувати теки, описано в інструкції, §4.2, а як подати таблиці у звіті —
у §5.

## У яких теках лежить кошик

Кошик — це шість файлів: сховище, `useCart`, `AddToCartButton`,
`CartLine`, сторінка кошика й шапка з лічильником. «Тек» — у скількох теках
вони лежать, «Теки» — шляхи цих тек через кому.

| Структура              | Тек | Теки                                                                                                                                                                                                                                                        |
| ---------------------- | --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| За типом файлів (§4.3) | 4   | src\store\cartStore.js ,src\hooks\useCart.js , src\components\AddToCartButton.jsx, src\components\CartLine.jsx , src\pages\CartPage.jsx, src\components\AppHeader.jsx                                                                                       |
| Гібридна (§4.7)        | 5   | src\shared\feature\cart\store\cartStore.js , src\shared\feature\cart\useCart.js, lab-src\shared\feature\cart\components\AddToCartButton.jsx, src\shared\feature\cart\components\CartLine.jsx, src\route\cart\CartPage.jsx, src\app\components\AppHeader.jsx |
| Пакет (§4.10)          |     |                                                                                                                                                                                                                                                             |

## Вибір структури

Описи проєктів, з чого обирати і як пояснити вибір — в інструкції, §4.8.
«Чому»: що в проєкті важливо і чому обрана структура для цього підходить.

| Проєкт                            | Структура                                                  | Чому                                                                |
| --------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------- |
| 1. Прототип на хакатоні           | За типом файлу                                             | Цей тип структури неймовірно простий для сортування та чудово підходить для проектів що варто зробити швидко, та є максимально прямолінійним тож кожен учасник знатиме що куди йтиме без потреби в будь якій комунікації                                                                                                                                 |
| 2. Блог і документація на Next.js | гібридна (за маршрутами + за типом файлу)                  | Ми маємо багато сторінок і кожна із них має свою розмітку, тож щоб працювати із цим проектом нам варто обрати спосіб що буде виконувати завдання так щоб ми не мали шукати який файл поміж них усіх, в такому підході ми зможемо доступитися до певної частини проекту без проблем та працювати із певним компонентом хуком або іншим елементом сторінки |
| 3. Адмінка для бариста            | за функціональніст                                         | ми маємо довгостроковий проект над яким працює ціла команда, це адмін панель тож в ній головна опора буде на функціональності тож буде краще розділити проект за ними щоб ми могли зручніше працювати із певними частинами програми                                                                                                                      |
| 4. Інтернет-магазин кави          | FSD                                                        | Цей проект є досить обємним, та ми маємо три команди що розробляють свою частину, та будуть активно оновлювати його, тож завдяки future sliced design розділити за тим що вони виконують та тим що може бути виконано що кожному робити свою роботу не заважаючи одне одному                                                                             |
| 5. Облік обладнання               | за маршрутами /(або гібридна за маршрутами та типом файлу) | на цей тип буде найлегше перейти єдине що нам потрібно це знати на якому екрані використовується той чи інший файл це довзолить нам продовжити працювати над проектом без великих змін                                                                                                                                                                   |
